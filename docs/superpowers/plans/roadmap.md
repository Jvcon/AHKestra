# AHKestra 研发路线图

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个成熟、稳定、可扩展的 AutoHotkey v2 上下文感知自动化框架，成为 Windows 平台上领先的效率工具。

**Architecture:** 基于插件化、事件驱动、上下文感知的架构，通过声明式 manifest 实现功能扩展，核心服务提供统一的能力支撑。

**Tech Stack:** AutoHotkey v2, C#/.NET 8.0 (用于 JSON 验证), JSON, YAML, Win32 API

---

## 一、项目当前状态

### 已实现的核心功能
- [x] **插件系统**: 动态加载、启用/禁用、manifest 验证
- [x] **上下文服务**: 多层上下文（稳定、活动、易变）组装与缓存
- [x] **事件总线**: 全局事件与动态事件（窗口事件）订阅/分发
- [x] **条件引擎**: 声明式条件表达式解析与评估（AND/OR/NOT）
- [x] **热键管理**: 常规热键、分层热键、序列热键（Leader 键）
- [x] **上下文菜单**: 基于上下文的动态右键菜单
- [x] **文本引擎**: 兼容 Espanso 的热字符串扩展
- [x] **配置管理**: JSON 配置加载、合并、持久化
- [x] **GUI 系统**: 设置界面、模式指示器、按键显示
- [x] **JSON 验证**: C# DLL 用于 manifest 模式验证

### 技术债务
- [ ] 缺乏正式的测试框架和自动化测试
- [ ] 日志系统仅输出到 OutputDebug，未实现结构化日志
- [ ] 错误处理较为基础，缺乏统一的错误报告机制
- [ ] 缺少 CONTRIBUTING.md 贡献指南文档
- [ ] 无 CI/CD 流程自动化

## 二、版本规划

### v1.1 — 稳定性与开发体验 (预计 1-2 个月)

#### 核心目标
- 完善日志系统
- 建立测试框架
- 完善开发文档

#### 任务清单

- [ ] **Task 1: 实现结构化日志服务**
  - 创建 `Core/Services/LogService.ahk`
  - 支持日志级别：DEBUG, INFO, WARN, ERROR
  - 支持输出到文件、OutputDebug、GUI 控制台
  - 替换现有 `PluginService.Log()` 调用

- [ ] **Task 2: 建立单元测试框架**
  - 创建 `tests/` 目录结构
  - 实现轻量级测试运行器 `TestRunner.ahk`
  - 为核心服务编写单元测试：
    - `tests/Core/Common/ConfigService.test.ahk`
    - `tests/Core/Conditions/ConditionEngine.test.ahk`
    - `tests/Core/Contexts/ContextService.test.ahk`

- [ ] **Task 3: 编写 CONTRIBUTING.md**
  - 开发环境搭建指南
  - 代码规范详细说明
  - 插件开发完整教程
  - PR 提交流程

- [ ] **Task 4: 改进错误处理**
  - 统一错误类继承体系
  - 实现错误恢复机制
  - 添加用户友好的错误提示（而非 OutputDebug）

## 五、风险管理

### 技术风险
- **AutoHotkey 性能限制**: 复杂场景下可能出现性能瓶颈
  - 缓解: 性能监控、缓存优化、关键路径优化
- **C# DLL 依赖**: .NET 运行时依赖增加部署复杂度
  - 缓解: 提供 AOT 编译选项、最小化依赖

### 生态风险
- **插件质量参差不齐**: 缺乏质量把控机制
  - 缓解: 插件签名机制、社区评审
- **用户学习曲线**: 上下文、条件等概念较复杂
  - 缓解: 完善文档、示例插件、可视化工具
